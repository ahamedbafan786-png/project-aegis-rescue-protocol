## 2. University Viva Examination Q&A

### Q1: What is the A* algorithm and why is it preferred over Dijkstra's algorithm?
**Answer:**
> *"A\* is an informed best-first search algorithm that finds the shortest path between a starting node and a goal. It selects nodes to expand based on the evaluation function:*
> $$f(n) = g(n) + h(n)$$
> *where $g(n)$ is the exact accumulated cost from the start node, and $h(n)$ is an estimated heuristic cost to the goal. While Dijkstra's algorithm expands nodes uniformly in all directions ($h(n) = 0$), A\* uses $h(n)$ to steer the search toward the target, significantly reducing the number of nodes expanded while guaranteeing an optimal path if the heuristic is admissible."*

### Q2: What does it mean for a heuristic to be "admissible" and "consistent"?
**Answer:**
> *"A heuristic $h(n)$ is **admissible** if it never overestimates the actual minimum cost to reach the goal, meaning:*
> $$h(n) \le h^*(n) \quad \forall n$$
> *where $h^*(n)$ is the true shortest distance to the goal. A heuristic is **consistent** (or monotonic) if for every node $n$ and each successor $n'$ generated by an action with cost $c(n, n')$:*
> $$h(n) \le c(n, n') + h(n')$$
> *satisfying the triangle inequality. Consistency ensures that once a node is expanded from the open set, its shortest distance is finalized and no closed node ever needs to be reopened."*

### Q3: Which heuristics did you implement and why?
**Answer:**
> *"We implemented:*
> 1. ***Manhattan Distance ($|r_1 - r_2| + |c_1 - c_2|$):** Admissible and consistent for 4-directional grid movement where movement is restricted to orthogonal cardinal directions.*
> 2. ***Octile Distance ($(\Delta r + \Delta c) + (\sqrt{2} - 2) \cdot \min(\Delta r, \Delta c)$):** Admissible for 8-directional movement where diagonal movement costs $\sqrt{2} \approx 1.414$. We also strictly prevent diagonal corner-cutting through blocked corners.*
> 3. ***Euclidean Distance ($\sqrt{(\Delta r)^2 + (\Delta c)^2}$):** Admissible for continuous free-space Euclidean movement.*
> *In all cases, we strictly maintain zero heuristic inflation to ensure mathematical optimality."*

### Q4: How is the Open Set implemented and what is its time complexity?
**Answer:**
> *"The Open Set is implemented using a custom **Binary Min-Heap** (`src/algorithms/minHeap.ts`). This yields:*
> - *Insertion (Push): $O(\log N)$*
> - *Extraction of Minimum $f(n)$ (Pop): $O(\log N)$*
> - *Peek Minimum: $O(1)$*
> *A naive unordered array would take $O(N)$ for extraction, which would severely degrade performance on large grids."*

### Q5: How did you implement dynamic replanning without visual glitches or clipping?
**Answer:**
> *"We decoupled the discrete logical grid coordinates $(r, c)$ from the floating-point visual coordinates $(x, y, \theta)$.*
> *The `RobotController` maintains an active waypoint queue. On every frame, an Invalidation Watcher inspects whether any upcoming waypoint has become blocked. If an obstruction is detected, the robot stops progression at its current safe grid cell, marks the route as invalidated, and executes an on-the-fly A\* search from its current cell to the destination. The new path replaces the remaining waypoints, and the robot resumes movement with smooth heading interpolation."*

### Q6: Does BFS always find the shortest path?
**Answer:**
> *"BFS is guaranteed to find the shortest path in terms of **number of edges (hop count)**. On uniform-cost graphs where every edge has a cost of 1.0, BFS finds the minimum-cost path. However, on weighted graphs (such as our rough terrain tiles which have a cost of 3.0), BFS may return a suboptimal path with fewer edges but higher total cost. Dijkstra and A\* are required to guarantee minimum cost on general weighted graphs with non-negative edge weights."*
